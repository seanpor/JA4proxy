## What went well

- **`/review-phase` consistently caught dependency and scope problems before
  any code landed.** The Phase 106 review (`docs/phases/complete/PHASE_106_review.md`)
  flagged five blocking issues — including a missed Redis-correctness SLO
  reference, a STYLE_GUIDE path typo, and the Phase 105 dependency status
  — none of which would have surfaced cheaply post-implementation. The
  review's output decomposed Phase 106 into 28 sub-tasks with explicit
  parallelism guidance, which then drove the Wave 1 fan-out.
- **Multi-agent fan-out for documentation-heavy phases reduced wall-clock
  by 3-4×.** Phase 106 Wave 1 (commits `abeccf9`, `bd62544`, `2832567`,
  `6a0623f`, plus this 106h commit) ran SERVICE_TARGETS, TCO_AND_LICENSING,
  RISK_REGISTER, traceability tooling, and QUALITY_PLAN concurrently with
  no merge conflicts because each owned a disjoint file set. The
  file-ownership rules in `CLAUDE.md` §Multi-Agent Coordination are doing
  their job.
- **pytest-xdist + machine-calibrated worker count keeps the full local
  Python sweep under 2 minutes.** `make test-calibrate` writes
  `.local/machine.mk` once; subsequent `make test` runs use that worker
  count. 2687 tests passing, 21 skipped (live-service-only) at the time
  of writing.
- **The Phase 118 pentest cadence (Phase 118a through 118vv) closed out
  ~30 findings with a uniform commit-message format** (`phase-118XX:
  remediate JA4PROXY-2026-NNNN <title>` paired with `phase-118XX: close
  JA4PROXY-2026-NNNN in findings register`). Future audit-evidence
  extraction is straightforward because the format is grep-friendly.
- **Coverage gates were raised mid-quarter without breaking anything.**
  Phase 207 raised the Go coverage gate from 50% to 80%; Phase 104
  brought 14 sub-80% Python files into compliance. Both landed without a
  flaky-CI period — the calibration script and parallelism kept signal
  high.

## What didn't

- **Phase 101 stranded on a long-lived branch and required a separate
  close-out review.** Branch `claude/phase-101-cross-phase-gaps` (last
  commit `5ffb736`, Apr 16) attempted 101d + 101k and self-declared the
  parent COMPLETE. The 2026-04-24 review (commit `d4f2b5b`) abandoned the
  branch without merging because spec items H6, H14, H16 were not
  attempted, and H7, H8, H15, M24, M25 were partial or alternative-design.
  Net effect: ~8 days of branch life, zero merge value, follow-up review
  cost ≈ 1 engineer-day.
- **Phase 105 was pulled in as a Phase 106 dependency without being
  scheduled — caused the placeholder-directory workaround.** Phase 106's
  audience-doc deliverables (TCO, SERVICE_TARGETS links, engineering-method
  links) target `docs/for-*/` directories Phase 105 was meant to create.
  Phase 105 was still PROPOSED when Phase 106 started. Workaround: Phase
  106 sub-task 1.2 pre-creates minimal placeholder READMEs with a
  `<!-- phase-106-placeholder -->` HTML comment so Phase 105 can grep-and-
  merge later. It works, but there will be reconciliation work whenever
  Phase 105 actually runs.
- **Retroactive REQ-tagging requires reading 7 phase docs in full** (Phase
  106d.2: tag Phases 15, 79, 82, 102, 103, 104, 200). The process is
  necessarily manual because acceptance criteria are prose; a regex
  retrofit would mis-tag. Scope-capped at 7 phases for that reason, but
  even 7 is a slow afternoon.
- **Phase 100 had to be reopened from COMPLETE.** Commit `5332b36` reopens
  it with re-verification after gaps were found post-close (`b995213`:
  "add gaps 100-F through 100-I from 2026-04-07 session"). The
  pre-phase-close gate let through an incomplete close. Cause: gaps were
  added retroactively, not all were wired into acceptance criteria at
  close time.
- **The two-phase pentest campaign produced more findings than the original
  Phase 118 plan budgeted for.** ~30 findings across 118a–118vv each
  required a remediation commit + a register-close commit, which inflated
  the commit-log noise and pushed the planned Phase 118 close out by
  several days. Phase 119 carries the rest.

## Method changes proposed

- **Auto-schedule declared dependencies.** When a phase doc declares "depends
  on Phase NN", and Phase NN is PROPOSED at the time the dependent phase is
  scheduled, the scheduler should either (a) refuse to start the dependent
  phase, or (b) auto-promote the dependency to scheduled. Prevents
  re-occurrence of the Phase 105 ↔ 106 placeholder-dir workaround. Measured
  in next retro: count of "missing-dependency" workarounds.
- **Time-cap unmerged phase branches.** Branches older than 14 days without
  a merged commit get a "stranded?" review automatically (similar to the
  Phase 101 review process, but earlier). Prevents 8-day strands turning
  into wholly-abandoned branches. Measured in next retro: median branch age
  at merge or abandonment.
- **Tighten the pre-phase-close gate to require manifest-acceptance-criteria
  parity.** A phase cannot be marked COMPLETE if any acceptance-criteria
  bullet is unchecked, or if the manifest's `acceptance_criteria_count`
  differs from the phase doc's bullet count. Closes the Phase 100 reopen
  hole. Implementation lands in Phase 106e tooling (or a 106-followup).
  Measured in next retro: count of phases reopened from COMPLETE.
