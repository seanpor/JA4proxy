\chapter{Metrics Reference}
\index{metrics}
\index{Prometheus}
\label{ch:metrics}

\begin{chapterquote}
All \ja\ metrics are prefixed \code{ja4proxy\_}. They are exposed on the
\code{/metrics} HTTP endpoint (default port 9090) in Prometheus text format and
scraped by the Prometheus instance at \code{:9090}.
\end{chapterquote}

\newthought{Metric naming follows} the Prometheus naming convention:
\code{ja4proxy\_\{subsystem\}\_\{metric\_name\}\_\{unit\}}. Counters always end
in \code{\_total}. Histograms emit \code{\_bucket}, \code{\_count}, and \code{\_sum}
automatically. All metrics are registered at startup; a metric that has never been
incremented will still appear in \code{/metrics} with a zero value.

\begin{notebox}[Monitor Bypass Volumes]
Monitor \code{ja4proxy\_bypass\_total} when modifying bypass configuration. A sudden
drop in \code{alpn} bypass traffic may indicate HAProxy misconfiguration or an upstream
change in ALPN negotiation.
\end{notebox}

Example PromQL:
\begin{lstlisting}[language=bash]
# ALPN bypass rate
rate(ja4proxy_bypass_total{type="alpn"}[5m])

# Spamhaus blocks per minute
rate(ja4proxy_bypass_total{type="spamhaus"}[1m]) * 60
\end{lstlisting}

This histogram is the primary tool for evaluating threshold configuration before raising

traffic with minimal false positive exposure.

Example PromQL:
\begin{lstlisting}[language=bash]
# 95th percentile score
histogram_quantile(0.95, rate(ja4proxy_risk_score_bucket[5m]))

# Fraction of connections scoring above 60
(
  sum(rate(ja4proxy_risk_score_bucket{le="100"}[5m]))
  - sum(rate(ja4proxy_risk_score_bucket{le="60"}[5m]))
)
/ sum(rate(ja4proxy_risk_score_bucket{le="100"}[5m]))
\end{lstlisting}

\section{Alert Rule Examples}
\index{metrics!alert rules}
\index{Alertmanager}

The following Prometheus alert rules provide a starting point for production alerting:

\begin{lstlisting}[language=yaml]
groups:
  - name: ja4proxy
    rules:
      # Redis connectivity — any failure is critical
      - alert: JA4proxyRedisErrors
        expr: rate(ja4proxy_redis_operations_total{result="error"}[2m]) > 0.5
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "JA4proxy Redis errors ({{ $value }}/s)"
          description: >
            JA4proxy is experiencing Redis errors. The fail-open
            guarantee means connections are still being allowed,
            but bans, rate limits, and signals are not being applied.

      # Blocking rate spike — may indicate attack or misconfiguration
      - alert: JA4proxyHighBlockRate
        expr: |
          rate(ja4proxy_connections_total{action="block"}[5m])
            / rate(ja4proxy_connections_total[5m]) > 0.3
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "JA4proxy block rate > 30%"
          description: >
            More than 30% of connections are being blocked.
            Verify this is not a false positive wave.

      # AbuseIPDB API errors — degraded enrichment
      - alert: JA4proxyAbuseIPDBErrors
        expr: rate(ja4proxy_abuseipdb_lookups_total{result="error"}[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "AbuseIPDB lookup errors"

      # No connections — possible proxy failure
      - alert: JA4proxyNoConnections
        expr: rate(ja4proxy_connections_total[5m]) == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "JA4proxy receiving no connections"
\end{lstlisting}
