\chapter{Deployment Reference}
\index{deployment}
\label{ch:deployment}

\begin{chapterquote}
\ja\ is deployed as a set of Docker containers orchestrated by Docker Compose
(development and single-host production) or Helm (Kubernetes multi-host production).
This chapter documents every service, environment variable, port, and network
requirement.
\end{chapterquote}

\newthought{The reference deployment topology} places \ja\ between a HAProxy
load balancer and the backend origin server. All traffic from the internet passes
through HAProxy (:443), which forwards raw TCP streams (with PROXY protocol v2
headers) to \ja\ instances (:8080). \ja\ then proxies allowed connections to the
backend (:443).

\begin{dangerbox}[Port Binding Policy]
Management services (Prometheus, Grafana, Loki, Alertmanager) bind to
\code{127.0.0.1} only. They must never be exposed on \code{0.0.0.0} in production.
Redis binds to \code{127.0.0.1}. Only HAProxy binds to \code{0.0.0.0:443}.
The proxy service binds to \code{127.0.0.1:8080} — it receives connections only
from HAProxy, which is on the same host or the same Docker network.
\end{dangerbox}

\subsection{HAProxy Configuration}
\index{HAProxy!configuration}

HAProxy must be configured for TLS passthrough with PROXY protocol v2 injection.
The critical sections of \code{haproxy.cfg}:

\begin{lstlisting}[language=bash]
frontend tls_in
    bind *:443
    mode tcp
    option tcplog
    default_backend ja4proxy

backend ja4proxy
    mode tcp
    option tcp-check
    server proxy1 proxy:8080 check send-proxy-v2
    # send-proxy-v2 enables PROXY protocol v2 header injection
    # TLS is NOT terminated — raw TCP passthrough
\end{lstlisting}

\begin{warningbox}[TLS Passthrough — Not TLS Termination]
HAProxy must be configured in TCP mode (\code{mode tcp}), not HTTP mode
(\code{mode http}). HTTP mode would terminate the TLS connection and re-encrypt it,
defeating the purpose of \ja. In TCP mode, HAProxy passes the raw TLS bytes through
to \ja\ unchanged. Only the PROXY protocol header is added by HAProxy.
\end{warningbox}

\subsection{Pre-built Container Images}
\index{GHCR}
\index{container images}

The Go proxy and management API are published to the GitHub Container Registry
(GHCR) on every merge to \code{main}. Running \code{docker compose pull} fetches
them automatically — no build toolchain is required on the production host:

\begin{bashcode}
docker compose pull && docker compose up -d
\end{bashcode}

Published image names:
\begin{itemize}
  \item \code{ghcr.io/seanpor/ja4proxy-go:main}
  \item \code{ghcr.io/seanpor/ja4proxy-management:main}
\end{itemize}

Both packages are public. Images are also tagged \code{sha-<commit>} for
pinning and \code{v*} on version releases.

\subsection{Traffic Insertion via iptables}
\index{iptables}
\index{traffic insertion}

When \ja\ is deployed on the same host as an existing service (nginx, HAProxy,
or the application directly), it can be inserted into the live traffic path
without changing any upstream configuration by using an iptables PREROUTING
redirect:

\begin{bashcode}
# Insert JA4proxy into the traffic path (:443 → :8443):
make traffic-on

# Remove JA4proxy from the traffic path (instant rollback):
make traffic-off
\end{bashcode}

These targets expand to:
\begin{bashcode}
# traffic-on:
sudo iptables -t nat -I PREROUTING -p tcp --dport 443 \
    -j REDIRECT --to-port 8443

# traffic-off:
sudo iptables -t nat -D PREROUTING -p tcp --dport 443 \
    -j REDIRECT --to-port 8443
\end{bashcode}

The redirect applies to incoming packets only (PREROUTING). Loopback traffic
is unaffected. Rollback is instantaneous and requires no service restart.
Requires \code{sudo iptables} on the host.

\subsection{Chart Structure}

The \ja\ Helm chart is located at \code{helm/ja4proxy/}. It deploys:
\begin{itemize}
  \item A \code{Deployment} for the proxy pods
  \item A \code{Service} (ClusterIP) exposing port 8080
  \item A \code{ConfigMap} containing \code{proxy.yml}
  \item A \code{Secret} for Redis password and API keys
  \item A \code{ServiceMonitor} for Prometheus Operator scraping
  \item (Optional) A \code{HorizontalPodAutoscaler}
\end{itemize}

\section{Production Deployment Checklist}
\index{deployment!checklist}

The following checklist must be completed before any production deployment:

\begin{enumerate}
  \item[\(\square\)] \textbf{Set \code{dial: 0}} — deploy in monitor-only mode
  \item[\(\square\)] \textbf{Pin image tags} — replace \code{latest} with a specific version
  \item[\(\square\)] \textbf{Change default passwords} — Grafana admin, Redis password
  \item[\(\square\)] \textbf{Secrets via Secret Manager} — no passwords in \code{.env} committed to Git
  \item[\(\square\)] \textbf{TLS certificate for backend} — verify backend cert is valid and trusted
  \item[\(\square\)] \textbf{Trusted upstream CIDR} — configure HAProxy address range in proxy config
  \item[\(\square\)] \textbf{GeoIP database present} — MaxMind GeoLite2 files mounted and current
  \item[\(\square\)] \textbf{Redis persistence enabled} — RDB or AOF configured; data volume mounted
  \item[\(\square\)] \textbf{Loki log shipping} — proxy logs flowing to Loki; retention policy set
  \item[\(\square\)] \textbf{Prometheus scraping} — metrics endpoint reachable; dashboards loaded
  \item[\(\square\)] \textbf{Alert rules loaded} — minimum alert set from Chapter~\ref{ch:metrics}
  \item[\(\square\)] \textbf{HAProxy in TCP mode} — not HTTP mode; TLS passthrough verified
  \item[\(\square\)] \textbf{Management ports bound to 127.0.0.1} — not 0.0.0.0
  \item[\(\square\)] \textbf{Verify score distribution} — run for 24h at dial=0; review histogram
  \item[\(\square\)] \textbf{Phase 14 hardening} — complete Phase~14 checklist before raising dial above 0
\end{enumerate}

\begin{notebox}[Phase 14 Hardening Prerequisite]
The Phase~14 production hardening checklist (\code{docs/DMZ\_DEPLOYMENT\_READINESS.md})
must be completed before raising the dial above 0 in production. Key gaps identified
at POC stage include: secrets management integration, Redis TLS, rate-limit self-protection
for the tarpit mechanism, and resource limit tuning. Do not skip this step.
\end{notebox}
