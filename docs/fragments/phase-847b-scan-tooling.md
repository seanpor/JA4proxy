- **Image gates count findings from Trivy JSON, not from table text (Phase 847b)**: `make scan-images` and `make scan-first-party` now run `scripts/trivy_image_report.py`, which parses Trivy's JSON report and prints a per-CVE table. The old `grep -v "Total:" | grep -c HIGH` counted severity *tokens* in Trivy's **grouped** table, where the severity is printed once per library — measured across a live capture of **14 real Trivy tables it returned `1` for every single one**, while Trivy's own line reported 4, 5 or 6; the pinned case is an image carrying **5** kin-openapi HIGHs reported as `1 HIGH`. Trivy's own correct `Total: 5 (HIGH: 5, CRITICAL: 0)` line was explicitly discarded by `grep -v "Total:"`. Worse, a **failed** scan counted as 0 findings, so an image Trivy could not read passed as clean — that silent pass is now exit 2, which reddens the target. Failure messages name `security/waivers.yaml` and the generated `.trivyignore.first-party` / `.trivyignore.third-party` instead of the `.trivyignore` deleted in Phase 822, and `.github/workflows/go-proxy-image.yml` no longer points at that deleted file. Also fixes a first/third-party list drift that offered the locally-built `ja4proxy-tap` image to the third-party (registry-pull) scan. See `docs/phases/complete/PHASE_847b.md`.
