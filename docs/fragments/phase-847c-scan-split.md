- **CVE handling is now split into a diff-scoped PR gate and a scheduled monitor (Phase 847c)**: `make scan` no longer reddens a PR because an upstream CVE was disclosed overnight. The new required check `scan-regression` (`make scan-regression`) works out which surfaces a PR actually touches — compose-pinned images, `Dockerfile*`, `requirements*.txt` — scans only those, and fails **only** on a finding absent from `security/baseline.json`, the recording of what `main` already carries. A PR touching nothing security-relevant scans nothing and passes in seconds; a PR that bumps an image or a dependency still has that surface scanned and still fails on a new unwaived HIGH/CRITICAL. The full scan is retained but de-required: it runs on push and schedule, on a PR only when the waiver set itself moved (`security/waivers.yaml`, `.trivyignore.third-party`, `.trivyignore.first-party`, `.pip-audit-ignores`), because a waiver change moves the gate's own inputs for *every* surface — without that, deleting a waiver would have been a silent no-op. The new `.github/workflows/scan-baseline-monitor.yml` runs daily, scans everything, diffs against the baseline (appeared / cleared / *digest moved*), files one deduplicated issue per unwaived finding (`[cve-baseline] <CVE> <surface>`), and reports the fixable-queue count Phase 847d consumes. Recording the first baseline caught a live identity bug: `rsplit(":", 1)` left `:tag` glued to the image name for digest-pinned refs, so the recorder keyed `image:redis` while the gate looked for `image:redis:7.4.11-alpine@sha256` — for five of the nine scanned images; identity is now the image *name* with the digest kept as provenance, so a routine tag bump carrying the same CVE set passes while a new CVE fails. Fail-safe throughout: a missing, unreadable or invalid baseline, an unrecorded surface, or a scan that errors all exit non-zero. See `docs/phases/complete/PHASE_847c.md`.
