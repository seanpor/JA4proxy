# ADR-013: Management UI Technology Choices

## Status: Accepted

## Context

Phase 13 requires a management web interface. Choices evaluated:

1. **React 18 + FastAPI (REST + SSE)**
2. Django with server-side rendering
3. Streamlit / Gradio (data science dashboards)
4. HTMX + FastAPI

## Decision

**React 18 + FastAPI with SSE (Server-Sent Events)**

## Rationale

### Why React 18 + FastAPI?

1. **FastAPI is already the backend framework** - No new dependency, consistent with existing codebase
2. **React + TypeScript provides type safety** - Critical for maintaining correctness across the client-server boundary
3. **Vite gives sub-second HMR** - Essential for developer productivity during frontend development
4. **shadcn/ui provides production-quality components** - Enables professional UI without dedicated design resources
5. **SSE is sufficient for the use case** - Unidirectional, proxy-friendly, automatic reconnection

### Why not Streamlit/Gradio?

- **No support for custom authentication** - Cannot implement the required Bearer token auth
- **No SSE support** - Cannot provide real-time connection feed
- **Limited REST API flexibility** - Cannot implement arbitrary REST endpoints
- **Not suitable for enterprise management interfaces** - Designed for data science dashboards, not security operations

### Why not HTMX?

- **Poor TypeScript integration** - Would complicate maintaining type safety
- **Limited component ecosystem** - Harder to build complex interactive components
- **Less suitable for SPA architecture** - Management UI benefits from client-side routing and state

### Why not Django?

- **Heavier ORM dependency** - Incompatible with existing async Redis usage patterns
- **Server-side rendering limitations** - Real-time features would require additional complexity
- **Template-based approach** - Less maintainable for complex interactive UIs

## Consequences

### Positive

- **Frontend build step in CI** - Ensures code quality before deployment
- **Two runtimes in development** - Python backend + Node build tools (manageable overhead)
- **Playwright for E2E testing** - Comprehensive browser automation testing
- **Modern developer experience** - Vite HMR, TypeScript type checking, React hooks

### Negative

- **Build complexity** - Requires Node.js in development and CI environments
- **Bundle size management** - Need to monitor and optimize frontend assets
- **Browser compatibility** - SSE has excellent support but requires fallbacks for very old browsers

## Implementation

```bash
# Frontend dependencies
npm install react react-dom react-router-dom @tanstack/react-query axios recharts
npm install -D typescript @types/react @types/react-dom vite @vitejs/plugin-react
npm install -D @playwright/test

# Build process
npm run build  # Produces zero warnings, zero TypeScript errors
```

## Alternatives Considered

### Alternative 1: Django with HTMX
- **Pros**: Simpler deployment, no build step
- **Cons**: Limited interactivity, harder to maintain complex state
- **Rejected**: Insufficient for real-time management requirements

### Alternative 2: Streamlit with Custom Extensions
- **Pros**: Rapid development, no frontend expertise needed
- **Cons**: Cannot implement required authentication and SSE features
- **Rejected**: Fundamental limitations for security requirements

### Alternative 3: SvelteKit
- **Pros**: Excellent developer experience, smaller bundles
- **Cons**: Less established ecosystem, fewer enterprise examples
- **Rejected**: React has stronger enterprise adoption and support

## Validation

The chosen architecture was validated by:

1. **Prototype implementation** - Built key components to verify feasibility
2. **Performance testing** - Confirmed SSE can handle required load
3. **Security review** - Verified authentication and authorization patterns
4. **Developer feedback** - Team comfortable with React + FastAPI stack

## Evolution

Future enhancements may include:
- **WebSocket upgrade** - If bidirectional communication needed
- **Micro-frontend architecture** - For very large scale
- **Progressive Web App** - Offline capabilities for field operations
