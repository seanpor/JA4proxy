# ADR-022: TAP HTTP Server — Standalone for Phase 20, Migrates to Phase 13

**Status:** Accepted
**Date:** 2026-03-28
**Phase:** 20 (Passive TAP/SPAN Mode)

---

## Context

TAP mode needs an HTTP interface for:
1. The EDL (External Dynamic List) server — pulled by firewalls
2. A health/status endpoint for monitoring
3. Future: TAP-specific dashboard panels in the management UI (Phase 13)

Phase 13 (Management UI) provides a FastAPI + React management plane, but it
was deferred until after Phase 15 (Go rewrite). TAP mode (Phase 20) needs HTTP
today.

Two options were considered:

1. **Standalone HTTP server in TAP mode** — aiohttp server embedded in the
   TAP sensor process (`src/tap/http_server.py`).

2. **Wait for Phase 13** — defer all HTTP endpoints until the management UI
   is built, then implement EDL and health there.

## Decision

Implement a **standalone aiohttp HTTP server** in the TAP sensor process for
Phase 20. This server will be absorbed into the Phase 13 management plane when
that phase is implemented.

The standalone server lives in `src/tap/http_server.py` and is started by
`TapSensor.start()` on a configurable port (default 9099).

## Rationale

Waiting for Phase 13 would leave TAP mode with no operational interface until
that phase is complete. Operators need:
- A `/health` endpoint for Docker/Kubernetes health checks.
- The EDL `/edl/{list_name}` endpoint for firewall integration.
- A `/status` endpoint showing capture statistics.

These are all read-only GET endpoints that are trivial to implement with
aiohttp and equally trivial to migrate to FastAPI later. The EDL server already
uses aiohttp (`src/tap/export/edl_server.py`).

## Migration Plan

When Phase 13 is implemented:
1. EDL server route is registered on the FastAPI app as a router.
2. TAP health/status endpoints moved to `/tap/health` and `/tap/status`.
3. `src/tap/http_server.py` is deprecated and removed.
4. `TapSensor` no longer starts its own HTTP server; instead it registers
   routes with the management API server via a plugin interface.

## Consequences

- TAP sensor listens on port 9099 (configurable). This port must be routed
  separately from the proxy port (8080).
- The standalone server does not require TLS — assumed to be on a trusted
  management network. Operators may add a TLS-terminating reverse proxy if
  needed.
- API paths use `/tap/` prefix to avoid clashing with Phase 13 routes:
  `GET /tap/health`, `GET /tap/status`, `GET /edl/{list_name}`.
