# Generated reference docs

> **STATUS: PROPOSED — plan for review. No code until approved.**

## Goal (plain language)

Three documents under `docs/reference/` are hand-maintained lists of things
that already exist somewhere else in the repo. All three have drifted, two of
them badly, and nothing catches it. Derive them instead.

## The measurement that motivated this

Taken 2026-08-05, while adding four `make` targets and one image during Phase
814a. Rather than hand-add rows to three lists, the lists were measured:

| Document | Reality | Documented | Missing | Stale (documented, no longer exists) |
|---|---|---|---|---|
| `MAKEFILE_TARGETS.md` | 187 targets | 167 | **56** | **36** |
| `SCRIPTS.md` | 119 scripts | 45 | **75** (63%) | — |
| `DOCKER_IMAGES.md` | 10 Dockerfiles | 7 | **4** | — |

Two details make this worse than the counts suggest:

1. **`DOCKER_IMAGES.md` does not list `deploy/docker/Dockerfile.go-proxy`** —
   the image that builds the production proxy. `docs/README.md` describes this
   file as "canonical registry of all images and pins". It is not.
2. **`MAKEFILE_TARGETS.md` is wrong in both directions.** 36 documented targets
   no longer exist (`go-parity`, `go-rollback`, `go-start`, `go-stop`,
   `go-switch` — leftovers from the Go migration, which finished in Phase 15).
   A reader following the doc gets "No rule to make target".

**Why nothing caught it:** `make lint-meta`'s documentation-sync check is
one-directional. It verifies that every command *mentioned in docs* exists in
the Makefile — not that every target in the Makefile is documented. It passes
today, on the numbers above.

This is the same failure mode this project has now hit three times:

| Phase | Hand-maintained list | What the drift cost |
|---|---|---|
| 810 | `TRIVY_IMAGES` | Three images had **never been scanned** — 113 real HIGH/CRITICAL findings |
| 812 | `KNOWN_ACTION_SHAS` | Every Actions bump red-lit CI until a human added a row by hand |
| **815** | These three reference docs | Readers following stale instructions; the canonical image registry missing the production image |

Phase 332 already established the fix pattern in this repo: `TODO.md` and
`PROJECT_STATUS.md` are **generated** from `manifest.yaml`, gitignored, and
regenerated by `make sync`. This phase applies that pattern to the last three
hand-maintained lists.

## Scope

In scope: one generator, one CI drift gate, and the deletion of the
hand-maintained content that the generator replaces.

Out of scope: turning *narrative* docs into generated ones. `RANGE.md`,
`PROGRAMME.md`, runbooks and guides are prose about *why*, and must stay
hand-written. This phase only targets lists that enumerate what already exists.

## Design

### Source of truth per document

Each list is derived from the artefact it describes — no new metadata file, no
second place to update.

| Document | Derived from | Already structured? |
|---|---|---|
| `MAKEFILE_TARGETS.md` | `Makefile` — the `target: ## description` help comments | **Yes.** 131 targets already carry `##` descriptions; `make help` renders them |
| `SCRIPTS.md` | `scripts/*.{sh,py}` header comment block + the Makefile target that invokes each | Partly — most scripts have a header docstring |
| `DOCKER_IMAGES.md` | `deploy/docker/Dockerfile*`, `src/*/Dockerfile`, plus the `image:`/`build:` stanzas in every compose file | Yes — and `scripts/check_image_versions.py --list-third-party` (Phase 810) already derives the third-party half |

The third-party image table stays as-is: Phase 810 already automated that
derivation. This phase adds the **first-party** half and wires both into the
same generated document.

### Deliverables

1. **`scripts/sync_reference_docs.py`** with two modes:
   - default — regenerate the three documents;
   - `--check` — regenerate into memory, diff against what is committed, exit
     non-zero on drift, printing the diff. This is the CI gate.
2. **`make sync` extended** to call it, alongside the existing roadmap sync, so
   there is one command that refreshes every generated document.
3. **A CI gate** in `ci.yml` running `--check`.
4. **Targets missing a `##` description get one** — 56 of them. This is the
   real work of the phase and it cannot be automated away: a generator can only
   surface a description someone wrote. Undescribed targets are listed in the
   generated doc under an explicit "undocumented" heading rather than silently
   omitted, so the gap stays visible instead of becoming invisible again.
5. **The 36 stale entries are deleted**, since the generator cannot emit a
   target that does not exist.

### What stays hand-written

Every one of these documents has hand-written prose around its tables —
`MAKEFILE_TARGETS.md`'s lane explanation, `DOCKER_IMAGES.md`'s version-pinning
rules. The generator must **preserve** those sections, replacing only content
between explicit markers:

```markdown
<!-- BEGIN GENERATED: make-targets -->
...table...
<!-- END GENERATED -->
```

This is the same containment approach used for other partially-generated files
in the repo, and it means a contributor can still add context without fighting
the generator.

### Should these become gitignored build artefacts?

Phase 332 made `TODO.md` / `PROJECT_STATUS.md` gitignored, because parallel
phase PRs kept conflicting on them. **Recommendation: no, not for these.**

These three are read by people browsing the repo on GitHub, where a gitignored
file simply does not exist, and by newcomers who have not run `make sync`.
`TODO.md` is a working roadmap; these are onboarding documentation. Keep them
committed and let the `--check` gate enforce freshness. Worth an explicit
decision at review rather than being assumed either way.

## Test strategy

- `tests/unit/test_sync_reference_docs.py`: a fixture Makefile with a known
  target set generates the expected table; a target with no `##` description
  lands in the "undocumented" section rather than vanishing; hand-written
  sections outside the generated markers survive a regeneration; `--check`
  exits non-zero on drift and zero when in sync.
- Run `--check` against the real tree to confirm it is green after the initial
  regeneration.
- `make lint-meta` must still pass — and its existing one-directional check
  becomes redundant once the doc is generated from the Makefile, so this phase
  should either remove it or narrow it to the prose sections.

## Acceptance criteria

- [ ] `scripts/sync_reference_docs.py --check` is green on `main` and runs in CI.
- [ ] All 187 Makefile targets appear in `MAKEFILE_TARGETS.md`; all 36 stale
      entries are gone.
- [ ] `DOCKER_IMAGES.md` lists every Dockerfile in the repo, including
      `Dockerfile.go-proxy` and `Dockerfile.attacker`.
- [ ] `SCRIPTS.md` lists every script in `scripts/`.
- [ ] Hand-written prose in all three documents is preserved verbatim across a
      regeneration (asserted by test, not by eye).
- [ ] Adding a new `make` target with a `##` description and running `make sync`
      updates the doc with no hand-editing.
- [ ] Deliberately deleting a target and running `--check` fails CI.
- [ ] `make lint`, `make test`, `make lint-docs-all` green.

## Out of scope

- Narrative documentation (`RANGE.md`, `PROGRAMME.md`, runbooks, guides).
- The third-party image table (Phase 810 already derives it).
- Making the documents gitignored — recommended against above; revisit only if
  they start causing merge conflicts.
- Writing genuinely good descriptions for all 56 undescribed targets in one
  pass. A one-line `##` each is the bar; prose can improve later.
