# Phase 94: Kubernetes Operator + CMDB/NetBox Integration

> **Prerequisites:** Phase 79 (Management API v2), Phase 83 (`ja4proxy-cli`),
> Phase 93 (Terraform provider — for shared client library patterns).

> **Context:** Phase 94 was split from the original Phase 83 (Infrastructure Automation).
> See PHASE_83.md for the split rationale.

---

## 1. Overview

For enterprises running OpenShift or Kubernetes using the DaemonSet topology
documented in Phase 76 (§5.3), this phase delivers:

1. **Kubernetes operator** — declarative management of JA4proxy configuration via
   Kubernetes CRDs, eliminating the need for out-of-band API calls after initial
   cluster deployment
2. **CMDB integration** (ServiceNow) — automatic asset registration on deploy
3. **NetBox integration** — read trusted CIDR ranges from NetBox rather than static
   config files, so network engineers can manage IP space in one place

This phase requires a running Kubernetes or OpenShift cluster for acceptance testing.
Plan for this infrastructure dependency before scheduling the sprint.

## 3. Custom Resource Definitions

### 3.1 `JA4ProxyConfig`

```yaml
apiVersion: ja4proxy.io/v1alpha1
kind: JA4ProxyConfig
metadata:
  name: prod-config
  namespace: security
spec:
  # Fields marked requiresRestart: true cannot be hot-reloaded.
  # The operator annotates the DaemonSet pods to trigger a rolling restart
  # when these fields change.
  redisUrl: "redis://redis.ja4proxy.svc.cluster.local:6379"   # requiresRestart: true
  bypassToggles:
    alpnBrowserBypass: true
    spamhausBypass: true
    tlsVersionBypass: true
    ja4WhitelistBypass: true
    mtlsBypass: true
status:
  conditions:
    - type: Reconciled
      status: "True"
      reason: ConfigApplied
      message: "PATCH /api/v1/config succeeded"
      lastTransitionTime: "2026-04-07T12:00:00Z"
  lastAppliedGeneration: 3
```

Hot-reloadable fields: `bypassToggles.*`. Fields requiring restart: `redisUrl`.
The operator MUST NOT restart pods for hot-reloadable changes (that would cause a
traffic gap). Use PATCH `/api/v1/config` for hot-reloadable fields and annotate the
DaemonSet pods with a config hash annotation for restart-required fields.

### 3.2 `JA4ProxyAllowlist`

```yaml
apiVersion: ja4proxy.io/v1alpha1
kind: JA4ProxyAllowlist
metadata:
  name: monitoring-tools
  namespace: security
spec:
  fingerprints:
    - ja4: "t13d1516h2_aabbccddeeff_aabbccddeeff"
      reason: "Internal monitoring"
      ticket: "CHG0001100"
    - ja4: "t13d1516h2_112233445566_aabbccddeeff"
      reason: "Partner API client"
      expires: "2027-01-01T00:00:00Z"
status:
  conditions:
    - type: Reconciled
      status: "True"
  entriesManaged: 2
  lastSyncTime: "2026-04-07T12:00:00Z"
```

Reconciliation: diff the spec list against GET `/api/v1/allowlist?managed_by=operator-k8s`,
POST missing entries, DELETE extra entries. Uses `managed_by=operator-k8s` to
distinguish from policy-applied and terraform-managed entries.

**Note:** `managed_by=operator-k8s` is a new value that requires Phase 79 API
acceptance. Confirm this value is accepted before writing the controller.

### 3.3 `JA4ProxyDial`

```yaml
apiVersion: ja4proxy.io/v1alpha1
kind: JA4ProxyDial
metadata:
  name: prod-dial
  namespace: security
spec:
  setting: 70
  ticket: "CHG0001234"
  notes: "Post shadow-mode validation"
  requiresApproval: false   # set true to gate the controller on four-eyes approval
status:
  conditions:
    - type: Reconciled
      status: "True"
  pendingDecisionId: ""     # non-empty when API returned 202
  currentSetting: 70
```

When the API returns 202, the controller sets `pendingDecisionId` in the status and
stops reconciling (no retry loop). The operator emits a Kubernetes event:
`Warning PendingApproval JA4ProxyDial/prod-dial dial change requires approval: dec-001`
This surfaces in `kubectl describe ja4proxydial prod-dial` and ArgoCD application health.

## 4. Operator Architecture

### 4.1 Reconciliation Loop

- **Trigger:** Kubernetes watches for changes to any JA4proxy CRD + timer (every 30s)
- **On change:** controller calls Management API to converge actual state → spec state
- **Idempotent:** controller checks current API state before making changes (same logic
  as Phase 82 `policy apply` — only POST if absent, only DELETE if stale)
- **Error handling:** on API error, requeue with exponential backoff (controller-runtime
  default). On 5xx, status condition `Reconciled=False` with the error detail.
- **Concurrency:** each CRD type has its own controller goroutine; they share the same
  Management API client with a connection pool (max 5 concurrent requests)

### 4.2 Admission Webhook

Validates CRDs **before** they are accepted by the Kubernetes API server:
- `dial.setting` must be 0–100
- JA4 fingerprints must match `[a-z0-9]{10}_[a-f0-9]{12}_[a-f0-9]{12}`
- `expires` must be a future ISO 8601 timestamp
- Unknown fields in `bypassToggles` rejected

The admission webhook runs as a separate HTTPS server on port 9443 inside the operator
pod. It requires a TLS certificate, managed by cert-manager (cluster dependency —
document in prerequisites). The `ValidatingWebhookConfiguration` object is deployed
by the Helm chart.

**cert-manager is a hard dependency.** Document this in `deploy/helm/ja4proxy-operator/README.md`
with installation instructions. Do not implement a manual certificate rotation
workaround — cert-manager is standard in enterprise Kubernetes clusters.

### 4.3 DaemonSet Safety

The operator-managed DaemonSet spec must include:

```yaml
spec:
  template:
    metadata:
      annotations:
        cluster-autoscaler.kubernetes.io/safe-to-evict: "false"
    spec:
      priorityClassName: system-node-critical   # prevent eviction under memory pressure
      terminationGracePeriodSeconds: 30         # allow in-flight connections to drain
```

The operator must NOT set `hostNetwork: true` unless the deployment specifically
requires it (document the security trade-off in the Helm chart README if enabled).

## 5. ArgoCD Integration

ArgoCD's default health check for Deployments/DaemonSets checks pod readiness only.
A pod that is `Running` but with Redis unreachable is not healthy. Configure a custom
health check in the Helm chart:

```yaml
# deploy/helm/ja4proxy-operator/templates/argocd-health-check.yaml
apiVersion: argoproj.io/v1alpha1
kind: ConfigMap
metadata:
  name: argocd-cm
  namespace: argocd
  labels:
    app.kubernetes.io/part-of: argocd
data:
  resource.customizations.health.ja4proxy.io_JA4ProxyConfig: |
    hs = {}
    if obj.status ~= nil then
      for _, condition in ipairs(obj.status.conditions or {}) do
        if condition.type == "Reconciled" and condition.status == "True" then
          hs.status = "Healthy"
          hs.message = condition.message
          return hs
        end
      end
    end
    hs.status = "Progressing"
    hs.message = "Waiting for reconciliation"
    return hs
```

Note: ArgoCD custom health checks require ArgoCD to be present in the cluster.
Gate this resource behind `{{ if .Values.argocd.enabled }}` in the Helm chart.

ArgoCD sync should target `GET /api/v1/health/deep` rather than pod readiness alone.
Configure an ArgoCD app health check annotation in the operator Deployment template:

```yaml
metadata:
  annotations:
    argocd.argoproj.io/health-check: "true"
```

## 6. CMDB Integration (ServiceNow)

Add a task to the existing Ansible post-deploy role in `deploy/ansible/roles/ja4proxy/`
(new file `tasks/cmdb_register.yml`, included conditionally):

```yaml
# deploy/ansible/roles/ja4proxy/tasks/cmdb_register.yml
- name: Register JA4proxy node in ServiceNow CMDB
  when: servicenow_enabled | bool
  servicenow.itsm.configuration_item:
    name: "{{ inventory_hostname }}"
    short_description: "JA4proxy TLS Security Proxy"
    asset_tag: "JA4PROXY-{{ inventory_hostname }}"
    install_status: "installed"
    ip_address: "{{ ansible_host }}"
    u_version: "{{ ja4proxy_image_tag }}"
    u_upstream_lb: "{{ upstream_lb_host }}"
    u_downstream_backend: "{{ backend_host }}"
    u_environment: "{{ deploy_environment }}"
    u_last_deployed: "{{ ansible_date_time.iso8601 }}"
    u_config_checksum: "{{ config_checksum.stdout }}"
  delegate_to: localhost
```

Default: `servicenow_enabled: false` in `deploy/ansible/roles/ja4proxy/defaults/main.yml`.
No ServiceNow instance required for tests — `when: servicenow_enabled | bool` skips
the task in CI.

## 7. NetBox Integration

Read trusted CIDR ranges from NetBox rather than static config — network engineers
maintain CIDRs in NetBox (where they already manage IP space).

### 7.1 Implementation

New file: `src/config/netbox_loader.py` (Python, for the Python analytics/config path)
and `internal/config/netbox.go` (Go, for the Go proxy config path):

```python
# src/config/netbox_loader.py
async def load_trusted_cidrs_from_netbox(netbox_url: str, token: str, tag: str) -> list[str]:
    """Fetch trusted upstream CIDRs tagged with `tag` from NetBox IPAM.

    Falls back to empty list (not an error) if NetBox is unreachable.
    Caller merges result with static_cidrs from config/proxy.yml.
    """
    async with aiohttp.ClientSession() as session:
        try:
            resp = await session.get(
                f"{netbox_url}/api/ipam/prefixes/?tag={tag}&limit=1000",
                headers={"Authorization": f"Token {token}"},
                timeout=aiohttp.ClientTimeout(total=5.0),
            )
            if resp.status != 200:
                logger.warning("netbox_loader: HTTP %d from NetBox, using static CIDRs", resp.status)
                return []
            data = await resp.json()
            return [p["prefix"] for p in data.get("results", [])]
        except Exception:
            logger.warning("netbox_loader: NetBox unreachable, using static CIDRs", exc_info=True)
            return []
```

```go
// internal/config/netbox.go
func LoadTrustedCIDRsFromNetBox(ctx context.Context, url, token, tag string) ([]string, error) {
    // Same logic as Python: HTTP GET with timeout, fall back to empty on any error
}
```

### 7.2 Config

```yaml
# config/proxy.yml
trusted_upstream_sources:
  netbox:                          # phase-94
    enabled: false                 # opt-in; default off
    url: "https://netbox.corp.internal"
    token: "${NETBOX_API_TOKEN}"
    tag: "ja4proxy-trusted"        # NetBox tag identifying trusted prefixes
    refresh_on_sighup: true        # reload from NetBox on SIGHUP in addition to file reload
  static_cidrs:
    - "10.0.0.0/8"                 # always trusted regardless of NetBox
```

### 7.3 Integration Flow

1. On startup and on SIGHUP: if `netbox.enabled`, call `load_trusted_cidrs_from_netbox()`
2. Merge result with `static_cidrs` (union, deduplicated)
3. Write merged list to the in-process pytricia trie
4. On NetBox unreachable: use `static_cidrs` only, emit `WARN netbox_unavailable`
5. Emit `ja4proxy_netbox_cidrs_loaded{status="ok|error"}` Prometheus counter

**Fail-open:** If NetBox is unreachable, the proxy continues with the last known set
of trusted CIDRs (or just static_cidrs on first boot). Never block startup waiting
for NetBox.

## 9. ADRs Required

| ADR | Decision | Options |
|-----|----------|---------|
| ADR-094a | Operator framework | `controller-runtime` directly (recommended, no code-gen magic) vs `operator-sdk` (higher-level, more magic) |
| ADR-094b | Admission webhook cert management | cert-manager (hard dependency, recommended) vs self-signed with rotation script |
| ADR-094c | `managed_by=operator-k8s` value | New value in Phase 79 API (requires coordination) vs reuse `managed_by=operator` with a label field |

ADR-094c is the most important to resolve early: adding `operator-k8s` to Phase 79's
allowed `managed_by` values requires updating the Phase 79 implementation. If Phase 79
is already merged, this becomes a Phase 79 patch. Confirm with the Phase 79 owner
before choosing the `operator-k8s` value.
