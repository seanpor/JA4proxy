# Environment Template Remediation

## Goal

Apply the PHASE_300 audit findings to the **canonical** template (`template.env`)
and remove the stale duplicate, so `cp template.env .env` yields a working stack
and there is exactly one source of truth.

> Scope note: this phase changes **`template.env`** only (plus deleting the
> orphan). It does **not** touch any operator's git-ignored `.env`.

## Implementation Plan

1. **Add the genuine gap to `template.env`.** In the
   `# SECURITY SECRETS (Placeholders — generated by init)` section, add:
   ```bash
   # Generate: openssl rand -hex 16   (or run the setup wizard, which fills these)
   HAPROXY_STATS_USER=ja4proxy
   HAPROXY_STATS_PASSWORD=REPLACE_ME_SECURELY
   ```
   These are required by `docker-compose.monitoring.yml` (`:?`) and were missing.

2. **Remove the orphan `.env.example`.** It is unreferenced and ships weak
   defaults. Delete it; if a discoverable name must remain, replace its contents
   with a one-line pointer: `# Use template.env — see docs. (.env.example is
   retired.)`.

3. **Add an optional, commented opt-in block to `template.env`** so operators
   discover (without being forced to set) the threat-intel and tuning keys:
   ```bash
   # ── Optional: threat-intel providers (leave unset to disable) ──
   # ABUSEIPDB_API_KEY=
   # OTX_API_KEY=
   # GREYNOISE_API_KEY=
   # VIRUSTOTAL_API_KEY=
   # MISP_API_KEY=
   # MISP_BASE_URL=
   ```

4. **Confirm generation guidance** is present for every secret placeholder
   (`REDIS_PASSWORD`, `REDIS_SIGNING_KEY`, `MANAGEMENT_JWT_SECRET`,
   `MANAGEMENT_ADMIN_PASSWORD`, and the new `HAPROXY_STATS_*`).

5. **Document local-`.env` hygiene** in the runbook (the `development3`-style
   typo etc.) — guidance, not a repo change.

## Out of Scope
- Editing any git-ignored `.env`.
- Adding *required* entries for optional/defaulted variables (would force
  operators to set things that work fine unset).
- Changing the setup wizard (`cmd/ja4p/main.go`) — it already generates these
  secrets; this phase only aligns the *fallback* `cp template.env .env` path.

## Test Strategy
1. `cp template.env .env`, fill the `REPLACE_ME_SECURELY` placeholders, then
   `make start` (or `make start-poc`) — **no** `*_is required` failures, including
   the monitoring stack (HAProxy exporter authenticates).
2. `grep -E '\\$\\{[A-Z_]+:\\?' deploy/docker/*.yml` — every required variable has
   a matching key in `template.env`.
3. `make test` and `make lint` stay green (docs/template-only change).

## Acceptance Criteria
- `template.env` contains every compose-`required` variable (incl.
  `HAPROXY_STATS_USER/PASSWORD`), each secret with a generation comment.
- The orphan `.env.example` is removed (or redirected to `template.env`).
- A fresh `cp template.env .env` boots the full stack with no required-variable
  errors.
- `manifest.yaml` records phases 300 and 301.

## Dependencies
- PHASE_300 audit (findings above).

## Next Phase
