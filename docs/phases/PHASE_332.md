# Merge-Race Reduction & CI Shift-Left

> **STATUS: PROPOSED — plan for review. No code until approved.**
> A tooling/infra mini-phase. Removes the recurring merge-conflict churn that
> parallel phase PRs hit, and trials a faster required-check path on GitHub.

## Problem

Parallel phase PRs keep colliding on the **same three files**, and the collisions
are almost entirely self-inflicted:

- `docs/phases/TODO.md` and `docs/PROJECT_STATUS.md` are **auto-generated** from
  `manifest.yaml` (`<!-- AUTO-GENERATED by scripts/sync-roadmap.py -->`) yet are
  **committed**, so every concurrent phase PR conflicts on them.
- `manifest.yaml` conflicts when two agents touch adjacent entries (an append next
  to a status-flip).
- Branch protection sets `strict_required: true` (**require up-to-date before
  merge**), so each time `main` advances a waiting PR must rebase — which re-runs
  ~6 min of checks and **reopens the race window**, producing the observed
  "force-push → wait → re-conflict" loop (seen live on PR #171 vs #169/#170).

The long-pole required checks are **Full Lint (~5 min)** and **Security Scan
(~6 min)**; **Full Test** is ~3 min and **Meta-Validation** ~1.5 min. The longer
the required path, the wider the race window.

## Goal

Three coordinated fixes plus a CI shift-left trial:

1. **Remove the generated docs as a conflict surface.**
2. **Split `manifest.yaml` into per-phase fragments** (mirroring the existing
   `docs/fragments/` CHANGELOG pattern) so phase edits stop contending.
3. **Enable a GitHub merge queue** so concurrent merges serialize and
   auto-rebase instead of being hand-rebased.
4. **Shift the heavy checks left**: AGENTS.md mandates a full local
   lint/scan/test before every PR, and we **trial** a trimmed required-check set
   on GitHub (slow scans demoted to advisory + main-push + nightly).

## Grounding note (2026-06-15)

Verified against `main`:

- The two roadmap docs carry the AUTO-GENERATED banner and are produced by
  `scripts/sync-roadmap.py` via `make sync`; `manifest.yaml` is the single source
  of truth. A `make`-level check already asserts they stay in sync
  (`Makefile:505` region; `tests/` covers it).
- The repo **already solved the identical contention for `CHANGELOG.md`** with
  one-file-per-change fragments under `docs/fragments/` — strong precedent for
  doing the same to the manifest.
- Branch protection: `strict_required: true`, **10** required contexts; the four
  named gates are Meta-Validation, Full Lint, Full Test, Security Scan
  (`AGENTS.md` branch-protection callout).
- `ci.yml` already triggers on `pull_request`, **`push`**, and **`schedule`** —
  so checks demoted from the *required PR* set still run on every push to `main`
  and nightly. This is the safety net that makes the trial reversible and safe.
- **Caveat that shapes fix 1:** GitHub's server-side merge (and the merge queue)
  does **not** execute *custom named* `.gitattributes` merge drivers — there is
  no shell on the merge runner. A regen driver therefore only helps **local**
  `git rebase`/`git merge`; it cannot resolve the conflict GitHub sees when it
  merges the PR. The only server-robust fix is to **stop committing** the
  generated files. The plan below leads with that and treats the local driver as
  an optional developer convenience.

## Scope

### Fix 1 — Generated roadmap docs (pick one; **A recommended**)

- **(A, recommended) Untrack them.** `git rm --cached docs/phases/TODO.md
  docs/PROJECT_STATUS.md`, add both to `.gitignore`, and keep `manifest.yaml` as
  the committed source. Update the existing sync-check so CI regenerates and
  *publishes* them (artifact and/or a scheduled commit to a `generated-docs`
  branch or Pages) rather than diffing committed copies. Net: nothing to conflict
  on, ever.
  - Trade-off: they no longer render in the repo tree on GitHub. Mitigation:
    publish to Pages / an artifact, or a nightly job that writes them to a
    dedicated branch.
- **(B, fallback) Keep committed + local merge driver.** Add to `.gitattributes`:
  ```
  docs/phases/TODO.md      merge=roadmap-regen
  docs/PROJECT_STATUS.md   merge=roadmap-regen
  ```
  ship `scripts/git-merge-roadmap.sh` (runs `make sync`, writes the regenerated
  file to the driver's `%A` output) and register it from a `make dev-setup`
  target (`git config merge.roadmap-regen.driver ...`). **Honest limitation:**
  fixes local rebases only; GitHub server merges/queue still conflict, so this
  does **not** by itself stop the PR-level race. Use only if untracking is
  rejected.

Files: `.gitignore`, `scripts/sync-roadmap.py` / Makefile sync+check targets, and
(for B) `.gitattributes`, `scripts/git-merge-roadmap.sh`, a `make dev-setup` target.

### Fix 2 — Per-phase manifest fragments

- Introduce `docs/phases/manifest.d/<phase>.yaml` (one file per phase), and make
  `scripts/sync-roadmap.py` assemble them into the consumed manifest (either
  regenerate `manifest.yaml` as another build artifact, or read the directory
  directly everywhere `manifest.yaml` is consumed).
- Migrate existing entries with a one-shot splitter script; keep `make
  lint-phases` green throughout.
- Each agent now edits only its own `manifest.d/<phase>.yaml` → adjacent-entry
  conflicts disappear at the source.

Files: `docs/phases/manifest.d/*` (new), `scripts/sync-roadmap.py`,
`scripts/split-manifest.py` (one-shot), `Makefile` (`sync`, `lint-phases`),
`AGENTS.md` / file-ownership table, any tooling that reads `manifest.yaml`.

### Fix 3 — GitHub merge queue

- Enable a merge queue on `main` (repo Settings → Branches, or the protection
  API) so PRs enter a queue that auto-rebases + re-tests each in order; no human
  force-pushes a waiting PR again.
- With the queue handling currency, re-evaluate whether `strict_required` is
  still needed (the queue is the safe replacement for require-up-to-date).
- Document the new flow in `AGENTS.md` (replace the manual-rebase guidance).

Files: branch-protection / ruleset config (admin), `AGENTS.md`.

### Fix 4 — CI shift-left + trimmed-required trial

- **AGENTS.md mandate:** before opening any PR, run the full gate locally and get
  it green — add a one-command **`make preflight`** target (`make lint && make
  scan && make test`) and require it in the Phase Close-Out Checklist.
- **Trial (time-boxed, reversible):** keep **Meta-Validation + Full Test**
  required on PRs; **demote Full Lint and Security Scan** from *required* to
  advisory PR checks. They keep running on every **push to `main`** and on the
  **nightly schedule** (already configured in `ci.yml`), so `main` stays guarded.
- Define explicit trial success criteria and an exit ramp (below).

Files: `AGENTS.md` (preflight + branch-protection callout), `Makefile`
(`preflight` target), branch-protection required-contexts list (admin),
optionally `ci.yml` (mark demoted jobs non-blocking on `pull_request`).

### Out of scope

- Rewriting individual CI jobs for speed (caching, sharding) — a separate
  optimization; this phase only changes *which* checks gate a PR.
- Any phase's functional code. This is tooling/process only.

## Implementation Plan

1. **Fix 1 (A):** untrack the two generated docs, gitignore them, adjust the
   sync-check to regenerate+verify in CI and publish the rendered copies.
2. **Fix 2:** add the splitter, generate `manifest.d/`, repoint
   `sync-roadmap.py` + `lint-phases`, update the file-ownership table.
3. **Fix 3:** enable the merge queue; reconcile `strict_required`; rewrite the
   AGENTS.md merge guidance.
4. **Fix 4:** add `make preflight`; update AGENTS.md pre-PR mandate; flip the
   required-context list for the trial; record the trial window + criteria.
5. Run `make sync`, `make lint-phases`, `make test`; land via PR through the
   (now-enabled) queue.

## Trial: success criteria & exit ramp

- **Window:** 2 weeks from merge.
- **Success:** (a) zero lint/scan regressions reach `main` undetected (the
  push/nightly runs catch any that slip); (b) median PR-open→merge time drops
  measurably; (c) no increase in reverted merges.
- **Revert trigger:** any lint/scan regression lands on `main` and is not caught
  by the push/nightly run within one cycle → re-add the demoted checks to the
  required set (single branch-protection edit; fully reversible).

## Test Strategy

- `make sync` is a no-op after Fix 1/2 (generated outputs regenerate identically
  from the assembled manifest); `make lint-phases` stays green.
- A test asserting `manifest.d/` assembles to the same logical roadmap the old
  `manifest.yaml` encoded (no dropped/renamed phases).
- Simulate the race locally: branch A and branch B each add a phase fragment +
  regenerate; confirm they merge **without** conflict (proving Fix 1+2 work).
- CI dry-run of the trimmed required set on a throwaway PR before flipping
  branch protection.

## Acceptance Criteria

- [ ] `docs/phases/TODO.md` and `docs/PROJECT_STATUS.md` are no longer a merge-
      conflict surface (untracked, or — fallback — auto-resolving locally).
- [ ] `manifest.yaml` content is sourced from per-phase `manifest.d/` fragments;
      two independent phase additions merge with no conflict.
- [ ] A GitHub merge queue is enabled on `main` and the AGENTS.md merge guidance
      reflects it (no more manual force-push-rebase loop).
- [ ] `AGENTS.md` mandates `make preflight` (full lint+scan+test) before every PR,
      and a `make preflight` target exists.
- [ ] The trimmed required-check set is live as a **time-boxed trial** with
      documented success criteria and a one-edit revert path; demoted checks
      still run on push-to-`main` and nightly.
- [ ] `make test` and `make lint-phases` pass cleanly.
