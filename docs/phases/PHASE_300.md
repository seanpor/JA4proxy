# Environment Variable Audit

## Goal

Reconcile the environment variables **referenced** by the code and Docker Compose
files against the variables **provided** by the canonical template, so an
operator who follows the documented setup never hits a missing/required-variable
failure — and remove stale config that causes confusion.

## ⚠ Canonical template: `template.env` (NOT `.env.example`)

The repository has **two** env templates, and only one is live:

| File | Size | Referenced by | Status |
|------|------|---------------|--------|
| **`template.env`** | 23 vars | `Makefile`, `.github/workflows/ci.yml` (`cp template.env .env`), `scripts/start-poc.sh` | **canonical** |
| `.env.example` | 6 vars | **nothing** | **orphan / stale** (ships weak defaults like `changeme`) |

All audit and remediation must target **`template.env`**. `.env.example` is an
abandoned duplicate and is itself a finding (see below).

> **Note on `.env`:** the working `.env` is **git-ignored** — it is the
> operator's local file and cannot be changed by the repo. Findings about a
> specific `.env` (e.g. a local `ENVIRONMENT=development3` typo) are **local
> hygiene only**, not repository changes.

## Method

1. **Code scan** — `os.getenv` / `os.environ.get` (Python) and `os.Getenv` (Go)
   across the tree; collect every referenced key.
2. **Compose scan** — extract `${VAR}` interpolations from `deploy/docker/*.yml`,
   split into **required** (`${VAR:?…}` or bare `${VAR}`) vs **defaulted**
   (`${VAR:-…}`, which need no template entry).
3. **Wizard scan** — keys the setup wizard (`cmd/ja4p/main.go`) writes to `.env`.
4. **Cross-reference** — required-by-compose ∖ present-in-`template.env` = the
   genuine template gaps. Classify everything else as *defaulted*,
   *wizard-generated*, or *optional* (has a code default).

## Findings

### `template.env` is largely complete (23 vars)
It already contains the management secrets, the full `HOST_PORT_*` family,
`COMPOSE_PROJECT_NAME`, `REDIS_*`, `GRAFANA_PASSWORD`, `BACKEND_*`,
`ENVIRONMENT`, `LOG_LEVEL`, `JA4PROXY_BUFFER_SIZE`, `JA4PROXY_MAX_CONNS`, with a
`# SECURITY SECRETS (Placeholders — generated by init)` section using
`REPLACE_ME_SECURELY`.

### Genuine gap: HAProxy stats credentials
`docker-compose.monitoring.yml` **requires** them
(`${HAPROXY_STATS_USER:?…}` / `${HAPROXY_STATS_PASSWORD:?…}`) and the wizard
generates them, but they are **absent from `template.env`**. So
`cp template.env .env` *without* running the wizard makes the monitoring stack
fail to start (`HAPROXY_STATS_USER is required`).

| Variable | Required by compose | Wizard-generated | In `template.env`? |
|----------|:---:|:---:|:---:|
| `HAPROXY_STATS_USER` | ✅ (`:?`) | ✅ | ❌ **gap** |
| `HAPROXY_STATS_PASSWORD` | ✅ (`:?`) | ✅ | ❌ **gap** |

(No other compose-required variable is missing from `template.env`.)

### Stale orphan: `.env.example`
Unreferenced by any script/CI, 6 variables, weak placeholder values
(`REDIS_PASSWORD=changeme`). It is the source of the "missing variables"
confusion and should be **deleted** (or reduced to a symlink/pointer to
`template.env`).

### Optional / defaulted (NOT template gaps — documentation only)
- **Threat-intel keys** (`ABUSEIPDB_API_KEY`, `OTX_API_KEY`, `GREYNOISE_API_KEY`,
  `MISP_API_KEY`, `VIRUSTOTAL_API_KEY`, `MISP_BASE_URL`) — opt-in; providers are
  disabled when unset.
- **Tarpit / metrics tuning** (`TARPIT_*`, `METRICS_BIND_HOST`,
  `METRICS_AUTH_TOKEN`, `PROXY_METRICS_URL`) — have code defaults or are set
  in-compose.
- **Go runtime / test flags** (`CONFIG_PATH`, `PORT`, `JA4PROXY_*`,
  `ALLOW_UNAUTH_*`, `*_TEST_*`) — defaulted in code; test-only flags must stay
  out of the operator template.

## Recommendations (→ PHASE_301)
1. Add `HAPROXY_STATS_USER` + `HAPROXY_STATS_PASSWORD` to `template.env`'s secrets
   section (placeholder + `openssl` generation comment), matching the existing
   `REPLACE_ME_SECURELY` style.
2. Delete the orphan `.env.example` (or replace it with a one-line pointer to
   `template.env`).
3. Add an optional, commented "threat-intel / tuning" block to `template.env` so
   operators discover the opt-in keys without them being required.
4. Document (don't fix in-repo) the local-`.env` hygiene items.

## Acceptance Criteria
1. Audit targets `template.env` (the canonical file); findings reflect it.
2. The two-template confusion is resolved (orphan removed/redirected).
3. Every compose-`required` variable is present in `template.env`.
4. This phase is recorded in `manifest.yaml`.
