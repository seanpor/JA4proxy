# PHASE 331 — Repair `make sync` (manifest epic indentation + loud validation)

## Status: COMPLETE

---

## Goal

`make sync` (and therefore the documented close-phase step that regenerates
`docs/phases/TODO.md` and `docs/PROJECT_STATUS.md`) was broken for every agent:

```
KeyError: '102 - 106 - 161 - 204 - 329'
```

This MICRO phase fixes the underlying data corruption and hardens the generator
so the same class of YAML typo can never again surface as an opaque traceback.

---

## Root Cause

In `docs/phases/manifest.yaml`, the `Operational Excellence & Lifecycle
Management` epic's `phases:` list was mis-indented:

```yaml
  phases:
  - 102      # 2-space indent (correct)
   - 106     # 3-space indent ┐
   - 161     # 3-space indent ├ folded into the previous plain scalar
   - 204     # 3-space indent │ → "102 - 106 - 161 - 204 - 329"
   - 329     # 3-space indent ┘
```

YAML treats the over-indented `   - 106 …` lines as a multi-line continuation of
the plain scalar `102`, collapsing five list items into the single string
`"102 - 106 - 161 - 204 - 329"`. `scripts/sync-roadmap.py` then evaluated
`manifest["phases"]["102 - 106 - 161 - 204 - 329"]` while rendering the epic
roadmap table and died with a `KeyError` that pointed nowhere near the manifest.

---

## Scope

### Files modified
- `docs/phases/manifest.yaml` — correct the indentation of the four folded list
  items to a uniform two-space indent (also registers Phase 331 itself).
- `scripts/sync-roadmap.py` — add `_validate_epic_phase_refs()`, invoked at the
  top of `generate_status()`, which raises a `ValueError` naming **every**
  offending epic and id (and explaining the mis-indent fold) before the table
  loop can hit a `KeyError`.
- `tests/unit/test_sync_roadmap.py` — add `TestEpicPhaseRefValidation` (3 tests):
  the exact folded-compound-id regression, a plain typo'd id, and a well-formed
  control that must still render.
- `docs/phases/TODO.md`, `docs/PROJECT_STATUS.md` — regenerated by `make sync`
  now that it runs (these are generated artifacts, not hand-edited).
- `docs/phases/PHASE_232c.md` — drive-by reconciliation: its frontmatter said
  `PROPOSED` and its banner `IN_PROGRESS` while the manifest already recorded it
  `COMPLETE` (the inconsistency landed on `main` via #167); aligned all three.

### Out of scope
- The `make sync` consistency check is **not** a required CI gate, so the stale
  `TODO.md`/`PROJECT_STATUS.md` on `main` were not blocking merges — only the
  documented close-phase workflow. No CI/workflow changes are needed.

---

## Why harden the script, not just fix the data

The data fix alone restores `make sync` today. The validation pass ensures the
**next** mis-indentation (an easy mistake in a 2800-line manifest edited by many
agents) fails with an actionable message —

> `manifest.yaml: epic(s) reference undefined phase id(s): epic 'Epic: …' → phase '102 - 106 - 161 - 204 - 329'. This is usually a mis-indented entry …`

— instead of an opaque `KeyError` that costs the next agent a debugging session.

---

## Test Strategy

`tests/unit/test_sync_roadmap.py::TestEpicPhaseRefValidation` parses synthetic
manifests (no filesystem writes):

- **`test_folded_compound_id_raises_clear_error`** — reproduces the exact bogus
  id; asserts `ValueError` naming the epic, the id, and `manifest.yaml`.
- **`test_unknown_single_id_raises_clear_error`** — a plain typo is reported the
  same way.
- **`test_well_formed_epic_refs_do_not_raise`** — a correctly-indented list still
  renders the epic table (guards against over-eager validation).
