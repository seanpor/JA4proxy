# SOC 2 Control Narrative — JA4proxy

**Applicable Trust Service Criteria:** Security (CC6–CC9), Availability (A1)

---

## CC6 — Logical and Physical Access Controls

### CC6.1 — Access control policies

JA4proxy enforces role-based access control on all management operations via JWT
tokens validated on every request. Four roles exist with strictly increasing privilege:
Auditor < Analyst < Operator < Admin. Role assignments are recorded in the audit log
(`management:audit_log`) with actor, timestamp, and IP address.

**Evidence artefacts (included in SOC 2 pack):**
- `04_rbac_configuration.json` — exported snapshot of current role assignments and API permissions
- `audit_log.csv` — operator-accessible audit entries for the evidence period

### CC6.2 — Authentication mechanism

All Management API access requires a short-lived JWT (default: 8-hour expiry) issued
after credential validation. Tokens are issued as `httpOnly` cookies to prevent XSS
extraction.  Token rotation is enforced via the Management API.

### CC6.6 — Restrictions on inbound traffic

JA4proxy evaluates every inbound TLS connection against the following controls before
forwarding:
- JA4 fingerprint blocklist (immediate RST)
- Spamhaus DROP/EDROP lists (immediate block)
- GeoIP country blocklist (immediate block)
- Risk score threshold based on the composite signal scorer

All decisions are logged to the Redis Stream (`ja4proxy:events`) for audit purposes.

## CC7 — System Operations

### CC7.1 — Detection of configuration changes

Every change to blocklists, allowlists, dial setting, and policy YAML is written to
`management:audit_log` with the actor's identity and change ticket reference. The
four-eyes dial approval workflow (Phase 82) enforces a secondary approver for dial
changes above 50.

### CC7.2 — Monitoring of system components

Prometheus metrics expose `ja4proxy_connections_total`, `ja4proxy_risk_score`,
and `ja4proxy_dial_current`. Grafana SLO dashboards
(Phase 63) alert when block rate drops below the configured baseline or error rate
exceeds the burn-rate threshold.

## A1 — Availability

### A1.1 — Capacity planning

Prometheus metrics include Redis memory usage, stream length, and per-node connection
throughput. Capacity runbooks are maintained in `docs/runbooks/`.

### A1.2 — Environmental protections

The Go proxy (Phase 15) runs in Docker containers with CPU and memory limits enforced
via `docker-compose.poc.yml`.  Redis persistence is enabled with AOF to prevent data
loss on restart.
